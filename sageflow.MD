### What it is

A particle flow field where ~1000 tiny particles follow an invisible vector field generated by 2D simplex noise. Particles leave short fading trails as they move, creating rivers of light that weave, converge, and split organically. The noise field evolves slowly over time so flow patterns shift. The user's mouse cursor creates a gentle vortex that swirls nearby particles.

The effect should feel like watching thought currents — contemplative, alive, hypnotic if you stare, invisible if you're reading content.

### File: `components/FlowFieldCanvas.tsx`

This is a `'use client'` component that renders a fixed full-viewport `<canvas>` element at z-index 0 behind all content. It should:

1. Use `useRef` for the canvas element
2. Use `useEffect` for the animation loop with `requestAnimationFrame`
3. Clean up the animation frame on unmount
4. Handle window resize (re-initialize particles, clear canvas)
5. Track mouse position via `mousemove` / `mouseleave` events

### Simplex noise

Use a compact 2D simplex noise implementation directly in the component (don't install a package for this). The classic approach:

- Skew factors: `F2 = 0.5 * (Math.sqrt(3) - 1)`, `G2 = (3 - Math.sqrt(3)) / 6`
- 8-direction gradient table: `[{x:1,y:1},{x:-1,y:1},{x:1,y:-1},{x:-1,y:-1},{x:1,y:0},{x:-1,y:0},{x:0,y:1},{x:0,y:-1}]`
- 256-entry permutation table, shuffled once at init, doubled to 512 for wrapping
- Returns values in range [-1, 1] multiplied by 70

Alternatively, if you prefer a cleaner approach, install `simplex-noise` from npm (`npm install simplex-noise`) and use `createNoise2D()`. Either works.

### Exact parameters (match these precisely)

**Particle system:**
- `PARTICLE_COUNT`: 1000
- Particle size: 0.4 to 1.5px (random per particle)
- Particle speed: 0.3 to 1.0 (random per particle)
- Particle lifespan: 200 to 500 frames (random per particle)
- Fade in: first 30 frames (linear 0→1)
- Fade out: last 30 frames (linear 1→0)
- Respawn at random position when dead or offscreen (20px bleed margin)

**Color distribution (by spawn probability):**
- 70% white (dust grey): `rgba(214, 214, 214, alpha)` — alpha range 0.06 to 0.16
- 20% sage (olive leaf): `rgba(148, 168, 126, alpha)` — alpha range 0.12 to 0.26
- 10% dusk: `rgba(155, 138, 122, alpha)` — alpha range 0.08 to 0.18

**Noise field:**
- `NOISE_SCALE`: 0.0015 (controls spatial frequency — how tight the flow patterns are)
- `NOISE_SPEED`: 0.0003 (controls how fast the field evolves over time)
- Primary angle: `simplex2(x * NOISE_SCALE, y * NOISE_SCALE + time * NOISE_SPEED) * PI * 4`
- Curl layer: `simplex2(x * NOISE_SCALE + 100, y * NOISE_SCALE + 100 + time * NOISE_SPEED * 0.7) * PI * 2`
- Combined: `cos(angle + curl * 0.3) * speed` for x, `sin(angle + curl * 0.3) * speed` for y
- The curl layer adds organic variation so particles don't all follow identical paths

**Velocity smoothing:**
- `vx += (targetVx - vx) * 0.08` — particles don't snap to new directions, they ease into them
- This creates smooth curved trails instead of jagged turns

**Trail rendering (critical for the visual effect):**
- Each frame, fill the entire canvas with `rgba(30, 29, 26, 0.06)` — this is the page background color at 6% opacity
- This overlays on the previous frame, causing old trails to fade out over ~15 frames
- Then draw each particle as a line segment from previous position to current position
- Line width = particle size, stroke style = particle color at lifecycle-adjusted alpha
- DO NOT use `clearRect` — the fade overlay IS the trail mechanism

**Mouse interaction:**
- `MOUSE_RADIUS`: 280px
- Track mouse via `mousemove`, reset to offscreen (-9999) on `mouseleave`
- For each particle within MOUSE_RADIUS:
  - Calculate distance and normalized direction from particle to mouse
  - Force strength: `(1 - distance / MOUSE_RADIUS) * 3.0`
  - Apply tangential force (vortex): perpendicular to the mouse direction, multiplied by `force * 1.2`
  - Apply slight inward attraction: toward mouse, multiplied by `force * -0.25`
  - The tangential force creates a swirling whirlpool effect
  - The attraction keeps particles from flying away

**Tangential force math:**
```
// mdx, mdy = particle position - mouse position
// mDist = distance
ax += (-mdy / mDist * force * 1.2) + (mdx / mDist * force * -0.25)
ay += (mdx / mDist * force * 1.2) + (mdy / mDist * force * -0.25)
```

**Resize handling:**
- On window resize: update canvas dimensions, clear to solid background color, reinitialize all particles at random positions

**Initial state:**
- Fill canvas with solid `rgba(30, 29, 26, 1)` before starting animation
- This prevents a flash of transparent canvas on load

### Performance notes

- 1000 particles at 60fps is well within Canvas 2D budget on modern hardware
- The noise function is called once per particle per frame (1000 calls) — this is lightweight
- The trail fade technique (overdraw with semi-transparent bg) is much cheaper than storing and drawing trail history arrays
- On mobile (< 640px viewport), consider reducing to 500 particles for battery life
- Use `{ passive: true }` on the mousemove listener

### What NOT to do

- Don't use Three.js or WebGL — overkill for 2D particles, adds bundle weight
- Don't use CSS animations or DOM elements for particles — Canvas is the only performant path at 1000 particles
- Don't clear the canvas each frame — the semi-transparent overlay IS the trail effect
- Don't use `requestAnimationFrame` with a timestamp-based delta — frame-counting is simpler and the visual doesn't need sub-frame precision
- Don't add particle-to-particle interactions (collision, attraction) — the noise field alone creates emergent patterns
